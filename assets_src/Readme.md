# 角色素材管线（Blender → 图集 → 引擎）

从建模、绑定、走路动画，到 8 方向渲染、拼图集、进引擎的完整流程。
**改任何一环之前先读一遍**，尤其是「规格」和「方向映射」两节。

---

## 1. 规格（改之前要想清楚）

| 项目 | 值 | 说明 |
|---|---|---|
| 相机 | 正交，旋转 X=60°、Z=45°，正交缩放 2.6，瞄准 `(0,0,0.85)` | X=60 表示俯 30°；`sin30°=0.5` 才有 2:1 菱形地砖 |
| 渲染 | 320 × 320，PNG，RGBA，胶片透明，帧率 10，色彩管理 Standard | 320 = 单元格的 2 倍，缩一半有超采样效果 |
| 地砖（地图） | 128 × 64 | config.h 的 TILE_WIDTH/TILE_HEIGHT，决定地面和角色站位，**和下面的精灵格无关** |
| 精灵格（贴图画布） | 160 × 160 | 图集里一帧的大小，游戏里 1:1 显示；角色 96 px 高，格子必须装得下 |
| 角色高度 | 1.7 m → 画面约 **190 px** → 精灵格内 **96 px** | 不是 1:1 投影，见下方公式 |
| 脚底位置 | 精灵格 y = **130** | `pivotY = 130/160 = 0.8125`，必须是整数 |
| 图集 | **960 × 1280**（6 列 × 8 行，每格 160×160） | 行 = 朝向，列 = 走路帧 |
| 走路动画 | 6 帧，每帧 0.1 秒（10fps） | 和 Blender 场景帧率一致 |
| 角色与地砖比例 | 96 / 64 = **1.5 格高** | 头顶约到第二个格子的中线 |

### 投影换算（重要）

斜 30° 俯视时，物体在画面上的高度**不等于**世界高度：

```
画面高度 ≈ 世界高度 × 0.866 + 占地深度 × 0.354
```

所以同样 1.7 m 高：

- 测试方块（底面 1×1 m）：约 **209 px**
- 角色（占地 0.54×0.38 m）：约 **190 px**

**这不是 bug**，是占地面积不同。曾经因为漏了这条，把 96 px 误判成 104 px，白查了半天。

### pivot 规则

`pivot × 160` 必须是整数（130 可以，131.5 不行），否则 1:1 像素对齐时角色会相对地砖抖 1px。

pivot 的**取值方法**是“站立帧脚底最低像素 ÷ 2”，**不是**“世界原点投影”：

- 站立帧脚底约在 320 图的 y=260 → 单元格 130 → `pivot = 0.8125`
- 世界原点投影约在 y=251 → 精灵格 125，照这个设，角色会陷进地面 5 px

## 2. 方向映射（最容易错）

**相机起始方位是 45°，所以渲染文件编号和游戏方向差 3。**

| 游戏方向 | 图集行 | 渲染文件 |
|---|---|---|
| N（上） | 0 | `hero_3_01..06.png` |
| NE | 1 | `hero_4_01..06.png` |
| E | 2 | `hero_5_01..06.png` |
| SE | 3 | `hero_6_01..06.png` |
| S（下） | 4 | `hero_7_01..06.png` |
| SW | 5 | `hero_0_01..06.png` |
| W | 6 | `hero_1_01..06.png` |
| NW | 7 | `hero_2_01..06.png` |

这套映射由 `pack_sheet.py` 里的 `ROW_TO_FRAME = [3,4,5,6,7,0,1,2]` 实现——**行序在拼图集时就排好，引擎里 `dir` 直接当行号**，不需要偏移常量。

改了相机初始方位、或者换相机重新渲染，这个数组要重算。

## 4. 从零重建

全部在 Blender 的 **脚本** 工作区里，用 文本编辑器 → **打开** 对应 .py → ▶ 运行。

### 4.1 建身体 — `build_body.py`

用 Skin 修改器沿一组“关节线”长身体：顶点 = 关节，半径 = 粗细，躯干半径写成 `(X, Y)` 二元组所以是扁的；再用细分磨圆。

**最后一步的归一化不能删**：Skin + 细分会让表面整体收缩（实测 1.7 m 会缩到 1.46 m、脚离地 12 cm），脚本会把高度拉回 1.7 m、脚底压到 z=0。

跑完打印：`身体完成：高度 1.700 m，最低点 0.000 m`。

### 4.2 绑骨架 + 走路 — `build_rig.py`

7 根骨头：`root / spine / head / leg.L / leg.R / arm.L / arm.R`，自动权重，然后写 6 帧走路关键帧。

| 骨头 | 头 (X,Y,Z) | 尾 (X,Y,Z) | 父级 |
|---|---|---|---|
| root | 0, 0, 0 | 0, 0, 0.62 | — |
| spine | 0, 0, 0.62 | 0, 0, 1.12 | root |
| head | 0, 0, 1.12 | 0, 0, 1.60 | spine |
| leg.L | 0.10, 0, 0.62 | 0.10, 0, 0 | root |
| leg.R | -0.10, 0, 0.62 | -0.10, 0, 0 | root |
| arm.L | 0.19, 0, 1.06 | 0.21, 0, 0.66 | spine |
| arm.R | -0.19, 0, 1.06 | -0.21, 0, 0.66 | spine |

跑完按空格预览：腿交替前后摆、手臂反向摆。腿是反的就说明符号错了，把 `poses` 里的角度取反。

> 注意：`Ctrl + Tab` 只有在**选中骨架**时才进姿态模式；选中的是网格时菜单里根本没有「姿态模式」。

### 4.3 渲染 — `render_frames.py`

8 方向 × 6 帧 = 48 张，写到 `//frames/`。

### 4.4 拼图集 — `pack_sheet.py`

```bash
python assets_src/hero/pack_sheet.py
```

按 `ROW_TO_FRAME` 重排方向、按帧号排列，输出 960×1280 的图集和 json。

### 4.5 引擎注册 — `src/main.c`

```c
Asset_Register(
    as->assetManager,
    101,                    // AssetID
    "hero/hero_sheet.png",
    0, 0, 160, 160,         // 一帧的源矩形
    0.5f, 0.8125f,          // pivot：130/160，脚底
    0, 0,                   // 格子锚点不用
    6, 0.1f, 6              // 6 帧走路，每帧 0.1 秒
);
```

绘制时把方向（行）和当前帧（列）都传进去：

```c
Render_Entity_Push(am, 101, x, y, 1.0f, (int)player.dir, player.currentFrame, LAYER_OBJECT);
```

`dir` 对应图集的行，`currentFrame`（0~5）对应列。帧计时器在 `player.c`：移动时每 0.1 秒 `currentFrame = (currentFrame + 1) % 6`，停下归 0。

## 5. 渲染前检查清单

每次批量渲染前扫一眼，任何一项错了，整批素材都要重渲：

- [ ] 相机 → 正交缩放 **2.6**
- [ ] 输出 → 分辨率 **320 × 320**、PNG、RGBA
- [ ] 渲染属性 → 胶片 → **透明** 勾选
- [ ] 帧率 **10**、帧范围 **1~6**
- [ ] 摄像机 + 灯光挂在 **CAM_RIG** 下（转支点 = 光跟着转）
- [ ] 角色 **1.7 m**、脚底在 **z=0**

## 6. 常见坑

1. **方向反了**：先确认相机起始方位，再检查 `ROW_TO_FRAME`。按 W 应显示背面朝上走（N 行）。
2. **角色抖 1px**：`pivot × 160` 必须是整数。
3. **脚浮空或陷进地面**：pivot 用“站立帧脚底最低像素 ÷ 2”，不要用世界原点投影。
4. **模型变矮、悬空**：Skin + 细分收缩，跑 `build_body.py` 里的归一化。
5. **尺寸和预期对不上**：先套投影公式，别直接拿世界高度当像素高度。
6. **渲染“完成”了但没有文件**：`F12` 只渲染当前一帧到窗口、不写盘；批量必须跑 `render_frames.py`。
7. **输出路径**：用 `//frames/`（相对 .blend），不要用 `/tmp/`（Windows 上是当前盘的 `\tmp`）。
8. **图集走 LFS**：`*.png` 已在 `.gitattributes` 里配好，提交时自动进 Git LFS。
